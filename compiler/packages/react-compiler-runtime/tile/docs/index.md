# React Compiler Runtime

React Compiler Runtime provides backwards-compatible runtime support for code compiled by the React Compiler. It offers polyfills for memoization APIs, runtime validation guards for hook usage rules, structural checking utilities, and performance monitoring instrumentation. This package primarily targets React versions 17-18, but also works with React 19+.

## Package Information

- **Package Name**: react-compiler-runtime
- **Package Type**: npm
- **Language**: TypeScript
- **Installation**: `npm install react-compiler-runtime`
- **Peer Dependencies**: react ^17.0.0 || ^18.0.0 || ^19.0.0 || ^0.0.0-experimental

## Basic Usage

This package is primarily used by code generated by the React Compiler and is not typically imported directly by application developers. The React Compiler automatically inserts calls to these runtime functions in compiled components.

```typescript
import { c, useRenderCounter } from "react-compiler-runtime";

// Example: Using memo cache (typically generated by React Compiler)
function CompiledComponent(props) {
  const $ = c(4); // Create memo cache with 4 slots

  // Compiler uses cache slots for memoization
  let t0;
  if ($[0] !== props.value) {
    t0 = props.value * 2;
    $[0] = props.value;
    $[1] = t0;
  } else {
    t0 = $[1];
  }

  return <div>{t0}</div>;
}

// Example: Using render counter for performance monitoring
function MonitoredComponent() {
  useRenderCounter("MonitoredComponent");
  return <div>Hello</div>;
}
```

## Capabilities

### Memo Cache Management

Create and manage memoization caches for React Compiler-generated code.

#### Create Memo Cache

```typescript { .api }
/**
 * Creates a memo cache array for storing memoized values. Re-exports
 * React.__COMPILER_RUNTIME.c if available (React 19+), otherwise provides
 * a userspace polyfill using React.useMemo for earlier React versions.
 *
 * @param size - Number of cache slots to allocate
 * @returns Array with specified size, filled with sentinel values
 */
function c(size: number): Array<unknown>;
```

The returned array is initialized with sentinel values (`Symbol.for('react.memo_cache_sentinel')`) to indicate empty slots. The cache persists across renders and is used by compiled code to store memoized values.

#### Reset Memo Cache

```typescript { .api }
/**
 * Resets all slots in a memo cache to empty sentinel values,
 * clearing all memoized data.
 *
 * @param $ - The memo cache array to reset
 */
function $reset($: Array<unknown>): void;
```

### Hook Usage Validation

Runtime guards for enforcing React hook calling rules.

```typescript { .api }
/**
 * Runtime validation for hook usage rules enforced by React Compiler.
 * Throws errors when hooks are called conditionally, indirectly, or
 * with incorrect naming conventions.
 *
 * This function validates that:
 * - Hooks are called directly (not through wrapper functions)
 * - Hooks are named with 'use' prefix following convention
 * - Components are returned as JSX, not invoked directly
 *
 * @param kind - Guard operation type:
 *   - 0 (PushGuardContext): Enter guarded context
 *   - 1 (PopGuardContext): Exit guarded context
 *   - 2 (PushExpectHook): Enter expected hook call
 *   - 3 (PopExpectHook): Exit expected hook call
 * @throws Error if hook usage rules are violated
 */
function $dispatcherGuard(kind: 0 | 1 | 2 | 3): void;
```

**GuardKind enum values:**
- `PushGuardContext = 0` - Marks the start of a guarded context where hooks should not be called
- `PopGuardContext = 1` - Marks the end of a guarded context
- `PushExpectHook = 2` - Marks the start of a context where hooks are expected
- `PopExpectHook = 3` - Marks the end of an expected hook context

**Common error scenarios detected:**
- Calling hooks through indirection: `call(useMyHook)` instead of `useMyHook()`
- Renaming hooks: `const renamedHook = useState` then using `renamedHook()`
- Invoking components directly: `AnotherComponent(props)` instead of `<AnotherComponent {...props} />`

### Structural Validation

Deep structural comparison for detecting unintended value changes.

```typescript { .api }
/**
 * Performs deep structural comparison between old and new values,
 * logging detailed error messages when differences are detected.
 * Used to validate that memoized values maintain structural consistency.
 *
 * Checks up to 2 levels deep and handles:
 * - Type changes
 * - null/undefined differences
 * - Array length and element changes
 * - Object property additions/removals/changes
 * - Map size, key, and value changes
 * - Set size and element changes
 * - React element type and props changes
 * - Primitive value changes (including NaN)
 *
 * @param oldValue - Previous value to compare
 * @param newValue - Current value to compare
 * @param variableName - Name of variable being checked
 * @param fnName - Name of function containing the check
 * @param kind - Type of check being performed
 * @param loc - Source location identifier
 */
function $structuralCheck(
  oldValue: any,
  newValue: any,
  variableName: string,
  fnName: string,
  kind: string,
  loc: string
): void;
```

Errors are logged to `console.error` in the format:
```
${fnName}:${loc} [${kind}] ${variableName}${path} changed from ${oldValue} to ${newValue} at depth ${depth}
```

Duplicate errors are suppressed using an internal `seenErrors` set.

**Depth limit**: Comparisons stop at 2 levels deep to avoid performance issues.

**Function handling**: Functions are intentionally skipped and not compared.

### Performance Monitoring

Track component render counts for performance analysis.

#### Render Counter Hook

```typescript { .api }
/**
 * React hook that tracks the number of times a component renders.
 * Registers a counter on mount, increments on each render, and
 * unregisters on unmount.
 *
 * @param name - Identifier for the component being tracked
 */
function useRenderCounter(name: string): void;
```

**Usage example:**

```typescript
function MyComponent() {
  useRenderCounter("MyComponent");

  return <div>Content</div>;
}

// Later, check render counts
const counters = renderCounterRegistry.get("MyComponent");
if (counters) {
  for (const counter of counters) {
    console.log("Render count:", counter.count);
  }
}
```

#### Render Counter Registry

```typescript { .api }
/**
 * Global registry mapping component names to sets of counter objects.
 * Each counter object has a `count` property tracking render count.
 */
const renderCounterRegistry: Map<string, Set<{ count: number }>>;
```

Each component name can have multiple counter instances (one per mounted instance of the component).

#### Clear Render Counters

```typescript { .api }
/**
 * Resets all render counters in the registry to zero without
 * removing the counter registrations.
 */
function clearRenderCounterRegistry(): void;
```

This function iterates through all counters and sets `count` to 0, preserving the registry structure.

## Implementation Notes

### React Version Compatibility

The `c` function automatically detects React version capabilities:
- **React 19+**: Uses native `React.__COMPILER_RUNTIME.c` if available
- **React 17-18**: Falls back to polyfill using `React.useMemo`

### Internal React APIs

This package accesses React internals through:
- `React.__CLIENT_INTERNALS_DO_NOT_USE_OR_WARN_USERS_THEY_CANNOT_UPGRADE` (newer React versions)
- `React.__SECRET_INTERNALS_DO_NOT_USE_OR_YOU_WILL_BE_FIRED` (older React versions)

These are used to access `ReactCurrentDispatcher` for hook validation in `$dispatcherGuard`.

### Sentinel Value

The package uses `Symbol.for('react.memo_cache_sentinel')` as a sentinel value to mark empty cache slots. This symbol is also added as a property to cache arrays for React DevTools detection.
